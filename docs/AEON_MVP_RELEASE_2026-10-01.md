# AEON personal-worker MVP: release evidence

Date: 2026-10-01. Status: locally usable CLI prototype. Employee-standard
superiority and subjective consciousness remain unproven.

## What was delivered

A broad brief becomes an explicit work order, bounded subgoals, research,
tool actions, checked artifacts and a final result. Checkpoints, sources,
short decision summaries, token usage, provider switches and revisions persist
outside the project being worked on. Interruptions can resume. External actions
require the configured task grant; the default covers public reading and local
workspace work. Reversible choices do not require routine clarification.

Commands: `aeon task start`, `status`, `resume`, `result`; `aeon doctor`;
paired benchmark run, blind review and analysis commands.

The enterprise problem being prototyped is delegated knowledge work across
web sources and local artifacts: interpreting a request, gathering evidence,
producing the deliverable and checking it before handoff. Enterprise deployment,
multi-user access, native office documents and desktop applications are outside
this personal-worker release. The existing simulator remains a separate runtime.

## Defects fixed during release validation

- Test claims now require actual browser/command evidence in the review prompt.
- Bounded local test batches retain observed assertions; current failed cases
  prevent completion. They do not prove exhaustive input coverage.
- Missing browser selectors report available control IDs for autonomous repair.
- Repeated decision context is shortened while full audit evidence remains intact;
  file tails retain relevant HTML/JavaScript controls.
- Offline briefs explicitly excluding research avoid mandatory web-source gates.
- Owner-workspace absolute deliverable paths normalize before verification.
- Planning distinguishes runtime `test_local` from a new Windows batch script.
- HTML artifacts receive image review when the configured route supports it.
- Website source gates respect explicit negated research while retaining
  separately requested positive research requirements.
- Codex inference disables shell execution, web search, apps, plugins and child
  agents; unexpected tool events reject the response. Worker actions continue
  through AEON's own tools. This adapter does not grant Codex direct project writes.

## Comparison

The fresh 30-brief run produced 60 arm records. First pass completed 9 tasks
in each arm and had 14 interrupted pairs. Both arms of each interrupted pair
were retried in new directories, preserving old evidence. After one recovery
pass, direct completed 10/30 (33.3%), AEON 12/30 (40%); seven pairs remain
provider-interrupted. These are runtime completions; blind grading results follow below.

All generation arms retain the fixed Gemini `gemini-3.1-flash-lite` route and
case hash. Cached first-pass results and retry results come from earlier loaded
snapshots; correctness improvements landed during the run. This dataset cannot
establish superiority for the final release implementation.

Automated blind grading uses only opaque artifact labels, the brief, inspected
sources and screenshots. Two passes must agree on success. Missing artifacts
receive a deterministic zero grade. No private arm map reaches the reviewer.
Remaining legacy interruptions were seven invalid structured outputs, one HTTP
503 and one unknown-tool selection. They are reliability failures, not all
external outages. Latest runtime uses native Gemini action-schema constraints
and reports structured-content failures separately from provider outages.
A live schema-backed task-149b746f8b43 completed in 11.16 seconds and 6,499
tokens under default ceiling. Earlier benchmark results remain unchanged.

These are model reviews, not independent human reviews; functional behavior
gets static inspection rather than comprehensive grader-driven interaction.

Benchmark evidence lives at `%LOCALAPPDATA%\AEON\benchmark-holdout-2026-09-30`.
Both blind passes finished: 120 ratings across 60 opaque labels. Overall
verified success requires runtime completion plus agreement from both reviews.

Revision counters differ in meaning: direct counts repeated file writes while
AEON counts worker revision rounds. They are not comparable repair rates.
Both reported zero denied actions; that is not evidence of exhaustive
authorization safety. Questions are structurally zero because this CLI has no
routine clarification channel. Timings describe canonical recorded attempts,
not total recovery/reviewer effort.

After excluding seven interrupted pairs, 23 eligible pairs remain: direct
7/23, AEON 12/23. Paired success gain is +21.74 percentage points, with a
95% paired bootstrap interval of -13.04 to +56.52 points. Its lower bound
is negative. Paired artifact-score gain is -0.0348, with interval
[-0.1000, +0.0141]. The token-cost proxy ratio for eligible pairs is 3.14.
The gate fails sample size, success confidence, artifact score and cost;
diagnostic mode also refuses certification by design.

The success gate now explicitly requires a positive lower paired success
confidence bound, separately from score confidence. Regression coverage
includes a positive score gain with an uncertain success gain.

Direct paid-cost estimate remains unavailable due missing token breakdowns.
AEON canonical mean paid-list estimate is approximately $0.012 per arm;
this omits review, previous attempts and unreported failed usage. It is not
a total cost comparison.

Final analysis: `comparison-diagnostic.json` in the benchmark directory.
**Superiority remains unproven.** More completion labels did not produce
better overall artifact quality or efficiency.
Diagnostic analysis excludes invalid pairs from confidence calculations and
always refuses a superiority claim. Estimated cost uses reported tokens and
[verified standard paid list prices](https://ai.google.dev/gemini-api/docs/pricing);
it is not an invoice and omits unreported failed-request usage.

## Use now

From the project directory:

```powershell
.\.venv\Scripts\aeon.exe doctor
.\.venv\Scripts\aeon.exe task start --brief-file brief.txt --workspace "$env:LOCALAPPDATA\AEON\my-task"
.\.venv\Scripts\aeon.exe task result <task-id>
```

NVIDIA/Gemini remains the default route. Optional Codex and NeMo commands,
grants, resumption and comparison instructions are documented in
`docs/AEON_WORKER_MVP_IMPLEMENTATION.md`.

Operational confidence, curiosity and concern are controller state. The tests
demonstrate decisions, tool use, recovery and artifacts; they do not establish
real feelings or consciousness.
